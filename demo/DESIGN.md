# 모아오더 화면 디자인

현대자동차 [CI의 블루 방향](https://www.hyundai.com/kr/ko/info/ci)을 참고한 공모전용 모아오더 디자인입니다. 공식 현대자동차 로고나 전용 폰트를 포함하지 않습니다.

- 기준 버전: `main`의 `405dd5b` (`demo_initial`)
- 디자인 작업 브랜치: `feature/hyundai-ui`
- 색상: 네이비 `#002c5f`, 블루 `#007fa8`, 포인트 `#75d5ee`, 배경 `#f4f5f7`
- 구조: 이동 경로 소개 → 목적지 / 대화 녹음 / 최종 주문 → 대화 이력
- 글꼴: 기기의 기본 글꼴. 외부 폰트 다운로드 없이 표시합니다.
- 앱 아이콘 원본: `demo/static/icons/mark.svg`

`demo/static/style.css`의 공통 변수를 사용해 화면 색상을 관리합니다. 녹음 파형의 캔버스 색상은 `demo/static/app.js`에 있습니다. PWA 테마 색상은 HTML과 manifest에 함께 반영합니다.

## 변경분 공유

프로젝트 폴더에서 다음 명령으로 기준 버전과의 차이를 확인합니다.

```bash
git diff main...feature/hyundai-ui --stat
git diff main...feature/hyundai-ui -- demo/static/index.html
```

브랜치의 커밋을 GitHub로 공유하려면 다음 명령을 실행합니다.

```bash
git push -u origin feature/hyundai-ui
```

이후 GitHub에서 `main`을 대상으로 Pull Request를 생성해 팀원이 검토할 수 있습니다. 병합 전까지 `main`의 기준 버전은 유지됩니다. Git 브랜치는 실행 중인 서버를 별도로 만들지 않으므로 현재 작업 폴더를 사용하는 서버에는 이 브랜치의 화면이 표시됩니다.

## 확인한 범위

기존 브라우저 검사 4개를 통과했습니다: 사람별 주문 및 변경 이력, 녹음 파형 및 저장 확인, 마이크 설정 및 복구, PWA 연결 및 오프라인 복구. 별도 임시 데이터와 합성 입력을 사용했고 실제 음성 인식 정확도 측정은 포함하지 않았습니다. 320 / 390 / 740 / 768 / 1024 / 1440px에서 가로 넘침이 없는 것을 확인했습니다. 실제 iPhone Safari 검증은 별도로 필요합니다.

서버가 정적 파일을 직접 제공하므로 화면 변경에 서버 재시작은 필요하지 않습니다. 녹음을 마친 뒤 페이지를 새로고침하세요. 설치형 웹앱에 이전 화면이 남으면 모든 모아오더 창을 닫고 다시 여세요. 홈 화면 아이콘은 기기의 캐시 정책에 따라 다시 추가해야 갱신될 수 있습니다.

## 목적지 검색과 마이크 파형

후속 작업 브랜치는 `feature/destination-search-waveform`이며 디자인 커밋 `40e075b`에서 시작했습니다.

- 목적지 목록은 항상 펼치지 않고, 검색창을 눌렀을 때 최대 6곳만 표시합니다. 이름·주소·분류·메뉴 이름을 검색하며 공백을 무시합니다. 지도 핀도 같은 매장과 메뉴를 선택합니다.
- 검색 대상은 `demo/stores.json`에 등록된 매장입니다. 전국 장소 검색 API나 실시간 메뉴 조회는 연결하지 않았습니다. 지도에서 임의의 위치를 선택할 때는 메뉴를 직접 입력합니다.
- 대기 중 마이크 아이콘을 누르면 로컬 입력 미리보기를 시작하고 다시 누르면 종료합니다. 미리보기는 음성을 저장하거나 서버로 전송하지 않습니다. 실제 저장은 ‘이 목적지로 출발 · 녹음 시작’으로 시작합니다.
- 파형은 최근 4초의 실제 입력 크기를 청색 막대로 표시합니다. 무음에서는 중앙 점선만 남습니다. 파형은 마이크 입력 표시이고 서버 저장 성공은 별도의 저장 상태로 확인합니다.
- 녹음 중 마이크 아이콘 또는 ‘파형 켜기’를 누르면 일시 정지된 오디오 처리를 재개합니다. 모바일 오디오 그래프는 무음 출력에 연결해 스피커로 마이크 소리를 재생하지 않습니다.
- 미리보기 종료, 녹음 전환, 화면 숨김, 늦게 도착한 권한 응답에서 마이크와 오디오 자원을 정리합니다.

`check_destination_preview.py`는 임시 매장 1,000곳의 검색 표시 제한과 지도·키보드 선택, 미리보기의 신호/무음 구분, 무전송, 권한 거부·취소 및 정리를 검사합니다. `check_recording_meter.py`는 색상에 의존하지 않고 실제 캔버스의 중앙선 밖 픽셀을 확인하며, 미리보기에서 저장 녹음으로의 전환도 검사합니다. 합성 음성을 사용한 Chromium 검증이며 실제 iPhone 검증을 대신하지 않습니다.

## 간결한 화면 구성

`feature/clean-ui`에서는 녹음 타이머와 영문 보조 제목, 반복 안내 문구를 제거했습니다. 녹음 시간 계산과 60분 자동 종료는 유지합니다. 기본 녹음 화면은 마이크·파형·주요 버튼 위주로 표시하고, 장치 선택 및 도움말은 접을 수 있는 ‘마이크 설정’에 모았습니다. 마이크 오류 발생 시 설정을 자동으로 펼칩니다. 저장 실패·분석 상태는 필요한 시점에 표시합니다. 좌표와 메뉴 설명은 해당 상세 영역에서 확인할 수 있습니다.

## 다크 / 화이트 테마

`feature/dark-white-themes`는 첨부 색상 이미지에서 추출한 차콜 `#444444`와 블루 `#002d5d`를 참고합니다. 공식 브랜드 규정 준수 인증을 의미하지 않습니다. 공통 구조는 `style.css`, 테마 색상과 표면 표현은 `themes.css`, 선택 상태는 `theme.js`에서 관리합니다.

처음에는 기기의 밝은/어두운 설정을 따르고, 사용자가 상단 버튼으로 선택하면 브라우저의 `moa-theme` 설정에 저장합니다. 저장소 접근이 제한되어도 현재 화면에서는 전환할 수 있습니다. 테마는 첫 렌더링 전에 적용하며 페이지 재시작이나 녹음 재연결 없이 전환합니다. 지도는 타일 레이어에만 색상 필터를 적용하고, 지도 핀과 안내·출처 표시는 테마 색상을 별도로 사용합니다. 파형은 두 테마 모두 어두운 배경과 밝은 청색으로 유지합니다.

`check_themes.py`에서 시스템 설정, 사용자 선택 유지, 저장소 차단, 네 화면 너비의 배치, 테마 전환 중 녹음 유지, 주문 결과 표시를 합성 입력으로 확인합니다. PWA 검사로 새 테마 파일의 오프라인 사용도 확인했습니다.

## 상단 브랜드 영역

`feature/compact-brand-header`에서 ‘함께 가는 길, 주문은 하나로.’와 경로 그림을 상단 모아오더 로고 영역으로 옮기고 본문의 큰 배너를 제거했습니다. 넓은 화면에서는 로고·문구·그림을 나란히, 좁은 화면에서는 로고·테마 버튼 아래에 문구와 그림을 배치합니다. 다크/화이트 및 320–1440px의 7개 너비를 확인했습니다.

## 브랜드 문구 정렬과 다크 색상 조정

`feature/refined-dark-brand`는 문구를 ‘모아오더’ 글자 바로 아래에 정렬합니다. 다크 테마의 배경은 `#121518`, 카드는 `#1c2025`, 주요 버튼은 `#164c82`와 흰 글자로 변경했습니다. 비활성 버튼은 중립 회색을 사용하고, 지도는 회색조로 표시합니다. 경로 그림과 화이트 테마는 유지합니다. 7개 화면 너비에서 문구의 수직 위치와 정렬, 테마·녹음 유지 검사를 확인했습니다.

## 녹음과 주문 분석 표시

`feature/recording-order-states`에서 목적지 기호를 위치 핀 SVG로 바꾸고, 메뉴 제목을 선택한 매장 이름 기반으로 표시합니다. 녹음과 입력 미리보기 중에는 파형만 표시하며, 종료하면 파형을 숨기고 마이크 아이콘을 다시 표시합니다. 미리보기 종료는 파형의 ‘입력 확인 종료’, 일시 정지된 파형의 재개는 ‘파형 켜기’ 버튼을 사용합니다.

‘최종 주문’에서 저장·대기·분석 상태를 큰 안내와 회전 표시로 강조합니다. 결과나 오류가 도착하면 진행 표시를 해제합니다. 분석 시작 요청이 실패한 경우에도 진행 표시를 유지하지 않습니다. 실제 진행률을 알 수 없으므로 임의의 퍼센트는 표시하지 않습니다. 브라우저 검사에서 합성 입력으로 녹음 전환, 파형 정지/재개, 분석 대기 표시와 최종 결과 전환을 확인합니다.

## 녹음 제어, 파일 업로드와 새 주문

`feature/recording-controls-upload`에서 다음 기능을 추가했습니다.

- 녹음 일시정지/재개: `MediaRecorder.pause/resume`을 사용하고 대기 중 트랙 입력을 비활성화합니다. 대기 시간은 분석에 보내는 녹음 길이에서 제외합니다. 일시정지 상태에서도 중지하거나 삭제할 수 있습니다. 화면을 벗어나면 녹음/일시정지 모두 저장 후 종료합니다.
- 녹음 중지: 현재 녹음을 저장하고 선택한 매장의 메뉴로 주문 분석을 시작합니다.
- 녹음 삭제: 확인창을 거쳐 현재 녹음 폴더와 분석 결과를 실제 삭제합니다. 인증과 동일 출처 검사를 적용하며 분석 중 삭제는 거절합니다. 다른 세션에는 영향을 주지 않습니다.
- 파일 업로드: WAV, MP3, M4A/MP4, OGG, WebM, FLAC를 최대 250MB/60분까지 받습니다. 조각 단위로 보내고 실패한 조각부터 재시도합니다. 서버가 전체 크기, 실제 음성 스트림과 길이를 확인한 뒤 모델에 전달합니다. 길이 메타데이터가 없는 파일 등은 WAV/MP3/M4A로 다시 올리도록 안내합니다. 실패 후 새로고침해 원본 파일이 사라진 경우 부분 파일을 임의로 분석하지 않습니다.
- 새로운 주문: 상단 및 결과 아래 버튼으로 목적지/메뉴/현재 결과를 비우고 새 세션을 시작합니다. 이전 주문은 최근 녹음에 남습니다.

`check_recording_controls.py`는 실제 브라우저 MediaRecorder와 합성 입력/생성 WAV로 일시정지 시간 제외, 재개, 일시정지 중 중지/삭제, 파일 업로드, 두 번째 조각 전송 실패 후 재시도, 매장 간 세션 분리와 양 테마를 확인합니다. 서버 단위 검사에서는 파일 실삭제, 인증, 분석 중 삭제 거부, 불완전/잘못된 파일 차단도 확인합니다. 사람의 실제 음성 인식 정확도 및 실제 iPhone 동작은 별도 확인 대상입니다.


## 기존 주문에 추가 녹음

`feature/append-order-recordings`에서 최근 녹음 제목 옆과 완료된 각 기록 옆에 ‘추가 주문’을 제공합니다. 매장과 메뉴는 최초 저장한 내용을 그대로 사용합니다. 새 녹음 또는 파일 업로드를 마치면 기존 음성과 새 음성을 16kHz 모노 WAV로 연결하여 화자 분리·ASR·문맥 분석 전체를 다시 수행합니다. 별개 분석의 화자 번호를 같은 사람으로 가정하거나 최종 수량을 단순 합산하지 않습니다. 전체 대화 안에서 변경/취소/추가를 다시 해석하므로 분석 시간은 누적 녹음 길이에 따라 늘며, 화자 번호는 재분석 결과에 따라 달라질 수 있습니다.

저장은 `order_id`로 묶인 불변의 이전 분석과 새 분석 리비전으로 구성합니다. 최근 녹음에는 주문당 한 줄과 최신 완료 결과를 표시하고, 미완료 추가 녹음은 ‘추가 녹음 이어보기’로 재시도/삭제할 수 있습니다. 추가 녹음이 실패해도 이전 완료 결과를 보존합니다. 동일 주문에 동시 추가는 차단하고 완료된 최신 리비전에서만 이어갈 수 있습니다. 예전 저장 형식도 원래 세션 ID를 주문 ID로 간주해 사용할 수 있습니다.

기록의 ‘최종 주문 결과’ 탭에서 합쳐진 주문과 녹음별 재생 구간을 보여 줍니다. 화자별 대화, 변경 이력, 전체 음성 재생과 JSON 내려받기는 같은 누적 타임라인을 사용합니다. 새로운 주문은 별도로 유지하며, 미완료 추가 녹음 삭제는 해당 추가분만, 완료된 주문 삭제는 그 주문에 속한 모든 녹음과 결과를 삭제합니다. 안내 확인창에서도 이 차이를 표시합니다. 누적 음성은 60분, 한 주문의 녹음은 100개까지 제한합니다.

검증: 서버 검사에서 실제 WAV 결합의 순서·중복 방지, 메뉴 스냅샷 상속, 추가·변경 연산, 실패/재시도, 동일 주문 동시 추가 차단, 주문별 삭제 범위, 서버 재시작 후 결과 복구 및 기존 저장 형식 호환을 확인합니다. `check_append_orders.py`는 합성 마이크 입력과 생성 WAV로 추가 녹음/업로드, 합쳐진 결과와 기록·내려받기·재접속, 실패 복구, 추가 녹음 삭제와 모바일 폭·두 테마를 확인합니다. 모델 응답은 검증용 고정 응답이므로 실제 음성 인식 정확도를 평가하는 검사는 아닙니다.


## 최근 녹음과 추가 주문 버튼 정리

`feature/compact-order-actions`에서 최근 녹음의 아이콘을 목적지와 같은 핀 SVG로 통일했습니다. 완료된 기록은 같은 카드 오른쪽의 ‘+ 추가 주문’ 버튼으로 이어가며 완료 상태 배지와 화살표, 카드 아래 별도 버튼 배치를 없앴습니다. 기록 열기와 추가 주문은 독립된 버튼으로 구성했습니다. 최종 주문 아래 버튼도 추가 주문으로 연결하고, 다른 매장으로 시작하는 새로운 주문은 상단 버튼에서 제공합니다.

녹음 제어는 일시정지(재개 시 재생), 중지, 휴지통 SVG와 함께 한 줄에 표시합니다. 좁은 화면에서는 반복되는 ‘녹음’ 접두어를 줄이고 접근성 이름에는 전체 역할을 유지합니다. 기존 브라우저 검사로 320/390/1440px에서 세 버튼의 같은 줄 배치, 핀·기록 내 추가 버튼, 결과 아래 추가 주문 연결, 일시정지/재개/삭제 및 추가 분석 흐름을 확인했습니다.
