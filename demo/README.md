# 휴대폰 직접 녹음 데모

2026-11-12: iPhone 홈 화면 설치(PWA), iOS 앱 소스, 재연결 화면, 로컬 HTTPS와 CPU 실행 옵션을 추가했다. 현재 설치/실행 절차는 [iPhone 앱 안내](../ios/README.md)를 따른다. Cloudflare 외부 접속은 사용자 동의 후 시도했지만 기관 네트워크에서 TCP·UDP 7844 연결이 모두 실패했다. 실패한 터널 프로세스는 종료했고, 외부 접속은 미완료다. 같은 LAN의 개발용 HTTPS는 별도이며 iPhone 인증서 설치가 필요하다. 앱 설치가 휴대폰 단독 분석을 의미하지는 않는다.

사용자가 녹음한 음성을 GPU PC에서 분석하는 웹 앱이다. 예제 CSV/음성을 자동으로 불러오지 않는다.

## 사용 순서

1. 접속 키가 포함된 HTTPS 링크 또는 QR코드를 휴대폰 Chrome/Safari로 연다. 앱 안의 내장 브라우저보다 일반 브라우저를 사용한다.
2. 세 매장 카드 또는 지도 위 번호를 누른다. 스타벅스 왕십리역9번출구점(8개), 맥도날드 한양대(5개), 백소정 한양대점(5개)을 선택할 수 있다.
3. 선택한 매장의 메뉴가 자동으로 불러와진다. 사용자가 제공한 총 18개 메뉴와 발화 별칭을 `demo/stores.json`에 등록했다. `상하이 세트`, `치즈카츠`, `딸기 라떼` 등도 해당 정식 메뉴에 연결한다. 매장 선택을 바꾸면 메뉴도 전부 교체한다. 등록된 매장의 이름·메뉴는 화면에서 임의 수정하지 않으며, 서버도 같은 카탈로그를 사용한다. 다른 위치를 지도에서 직접 지정하면 별도 메뉴를 입력할 수 있다.
4. `이 목적지로 출발 · 녹음 시작`을 누르고 마이크 권한을 허용한다. 지도 팝업에서도 바로 시작할 수 있다.
5. 두 사람이 각자 주문을 말하고, 원하는 경우 메뉴를 바꿔 말한다. `녹음 마치고 주문 정리`를 누르면 저장된 음성을 분석한다.
6. 녹음 영역 아래의 **최종 주문**에서 사람마다 마지막으로 선택한 메뉴와 수량을 확인한다. 참여자 수에 맞춘 서로 다른 사람 아이콘과 번호로 구분하며, 대화 원문과 변경 이력에도 같은 아이콘을 쓴다. 발화 시각을 눌러 원음을 재생하고 JSON을 내려받을 수 있다. 아이콘은 실제 외모나 신원을 추정한 것이 아니다.

녹음 중에는 이 화면을 켜둔다. 모바일 운영체제가 화면 잠금이나 다른 앱 전환으로 마이크를 중단할 수 있다. 길 안내 링크는 외부 지도 서비스를 연다. 브라우저에서 백그라운드 녹음과 길 안내의 동시 지속을 보장하지 않으며, 이 부분은 추후 Android 앱에서 구현한다.

녹음 카드에는 실제 마이크 입력 크기를 최근 8초 동안 쌓아 보여 주는 파형이 표시된다. 소리가 없으면 평평해지며 `소리 입력을 기다리는 중`으로 표시된다. 파형은 마이크 입력 상태이고, 그 아래 `서버 저장 확인 · … KB`는 서버가 업로드를 확인한 용량이다. 저장 연결이 끊기면 별도 상태가 표시된다. 브라우저가 오디오 분석을 일시 정지한 경우 `파형 켜기`를 누른다. 녹음 종료 후에는 마지막 파형을 유지하며 새 녹음이나 다른 이력을 열면 초기화된다.

## 실행 및 접속

GPU PC에서 `bash demo.sh`를 실행하면 접속 키가 포함된 전체 주소가 터미널에 표시된다. 이를 같은 PC의 Chrome 또는 Edge에서 열고 마이크를 허용하면 바로 녹음할 수 있다. 서버는 `127.0.0.1:8765`에만 바인딩한다. `scripts/demo_access.py`는 필요할 때 링크와 QR을 별도로 만들며, 네트워크 공개 작업은 하지 않는다.

휴대폰의 마이크에는 HTTPS가 필요하다. Cloudflare를 경유하는 데이터 전송에는 사용자가 명시적으로 동의했으며, 현재 장애는 승인 문제가 아닌 네트워크 연결 실패다. 기관 네트워크에서 Cloudflare 터널의 7844번 외부 연결을 확인해야 한다. 연결이 정상화되고 인증 검사가 통과한 뒤에만 외부 주소/QR을 배포한다. 접속 링크를 가진 기기만 API에 접근할 수 있다. GPU PC와 서버, 터널이 계속 실행되어 있어야 하며 임시 주소는 재실행 때 변경될 수 있다.

## 마이크를 찾지 못할 때

마이크는 서버가 아니라 **페이지를 연 기기와 브라우저**에서 가져온다. Codex 내장 미리보기에서 `NotFoundError`가 발생하면, 화면의 **다른 브라우저용 링크 복사**를 눌러 별도로 실행한 Chrome/Edge/Safari의 주소창에 붙여넣는다. 현재 표시된 포트 전달 주소를 그대로 사용하므로 사용자 PC의 `localhost:53525` 등을 서버의 `localhost:8765`로 바꾸지 않는다. 포트 전달을 쓰는 동안에는 Codex를 켜 둔다.

**마이크 확인**은 선택한 입력 장치를 약 3초 동안 확인하며 음성을 저장하거나 서버에 업로드하지 않는다. 기본 장치 외에 브라우저가 공개하는 마이크를 선택할 수 있다. 녹음 중에는 장치 변경을 막는다. 브라우저가 숨긴 장치나 물리적으로 없는 마이크를 앱이 만들어 낼 수는 없으므로, 일반 브라우저에서도 실패하면 해당 기기의 소리 설정에서 입력 장치와 브라우저 마이크 권한을 확인한다. 진단 메시지는 장치 없음·권한 거부·다른 앱 사용 등의 원인을 구분한다.

`scripts/check_microphone_setup.py`는 합성 음원으로 입력 확인의 비저장, 오류별 안내, 자원 해제, 전달된 포트 유지, 지정한 마이크 사용, 실패 후 실제 MediaRecorder 복구를 검사한다. 사용자의 물리 마이크나 Codex 미리보기의 마이크 전달을 검증한 것은 아니다.

인증은 32바이트 난수 키, HttpOnly 쿠키, 공개 호스트의 Secure 쿠키, 요청 출처 검사로 구성된다. 전체 링크를 열면 키는 쿠키로 교환되고 주소창에서 제거된다. 녹음 API와 원음/결과 다운로드 모두 인증이 필요하다. 링크 소유자는 같은 데모의 전체 녹음 이력에 접근하므로 다중 사용자 서비스용 권한 모델은 아니다.

## 처리와 저장

현재 지도는 Leaflet/OSM이며 네이버 지도 API나 네이버 메뉴 자동 조회를 사용하지 않는다. 메뉴 출처는 사용자 제공 목록이다. 지도 좌표의 확인 출처는 `stores.json`의 `location_source`에 기록했다. 메뉴의 가격·판매 여부는 추정하지 않는다. `맥스파이스 상하이 버거 세트`는 사용자가 적은 이름 그대로 저장하고, `맥스파이시 상하이 버거 세트`는 발화 별칭으로만 추가했다.

- 1초 단위 MediaRecorder 조각을 순차 업로드한다. 전송 실패는 재시도하며 미전송 조각이 있으면 탭을 유지한 채 업로드를 재개할 수 있다.
- 녹음 종료 후 Nemotron 화자분리 → 겹침 구간 분리 → Whisper 한국어 ASR → Qwen 주문 변경 추론을 실행한다. 추론 작업은 GPU에서 하나씩 처리한다.
- 목적지와 메뉴 목록은 녹음 시작 시 고정해 다른 매장/녹음과 섞이지 않게 한다.
- 최대 녹음 60분/250MB, 메뉴 100개. 스트리밍 diarization과 짧은 ASR 구간, 제한된 LLM 문맥을 사용한다. 이 한도 전체의 실기기 성능은 미검증이다.
- 화자 번호는 한 녹음 안에서만 의미가 있다. 장시간 녹음, 차내 소음, 동시 발화의 정확도는 직접 검증이 필요하며 모호한 발화/겹침은 확인 대상으로 표시한다.
- 휴대폰에서 모델을 실행하지 않는다. GPU PC에는 현재 모델/의존성이 설치되어 있다. 실제 앱에서 사용할 서버/온디바이스 배치는 별도 결정한다.

`demo/sessions/<녹음ID>/`에 다음을 보관한다.

| 파일 | 내용 |
| --- | --- |
| `session.json`, `menu.json`, `trip.json` | 녹음 상태, 목적지·메뉴 스냅샷, 화자 표시 이름 |
| `chunks/`, `recording.webm` 또는 `recording.m4a` | 업로드 조각과 합친 원음 |
| `analysis_001/utterances.jsonl` | 누가 언제 무엇을 말했는지 |
| `analysis_001/orders.json`, `order_events.jsonl` | 최종 주문 초안과 변경 이력 |
| `analysis_001/metrics.json`, `analysis_001.log` | 처리 시간, 자원 사용량, 분석 로그 |

실패한 분석을 재시도하면 `analysis_002/`처럼 새 폴더를 사용한다. 브라우저 새로고침 후 기존 결과/저장된 녹음을 다시 열 수 있다. 전송되지 않은 조각은 새로고침 시 복구되지 않는다. 취소한 녹음은 최근 목록에서 숨겨지지만 저장된 조각은 자동 삭제하지 않는다.

## 검증 범위

`python -m unittest discover -s tests -v`: 주문 변경, 화자/세션 분리, 인증, 조각 순서·중복 전송, 분석 실패 후 재시도, 무발화 결과 등을 검증한다.

`scripts/check_demo_browser.py`: 390px 모바일 화면에서 Chromium 가상 마이크 → 실제 MediaRecorder → 업로드 → 실제 GPU 파이프라인 → 결과 표시 → 새로고침 복원을 검증한다. 지도 타일은 테스트 중에만 대체하여 자동 대량 요청을 하지 않는다. **가상 마이크의 테스트 신호이므로 사람의 음성 인식 정확도나 실제 휴대폰 테스트를 의미하지 않는다.** 테스트 데이터는 `demo/test-artifacts/`에 격리되며 실제 앱의 녹음 이력에 나타나지 않는다.

`scripts/check_recording_meter.py`: 제어 가능한 합성 오디오를 실제 브라우저 녹음기에 입력하여 소리/무음의 파형, 서버 응답 전 저장 완료 표시 방지, 업로드 실패, 오디오 분석 재개, 종료·초기화를 검증한다. 음성 인식 모델은 이 UI 검사에서 실행하지 않는다.

`scripts/check_demo_results.py`: 합성 결과로 마지막 메뉴 변경 반영, 2명/8명의 서로 다른 사람 아이콘, 원문과 아이콘 대응, 새로고침 복원, 새 녹음 시 이전 주문 제거, JSON 다운로드와 320/390/1440px 화면을 검증한다. 현재 UI는 이름 편집 대신 아이콘과 번호로 참여자를 표시한다.

2026-11-11 확인: 자동 검사 20개 통과, 가상 마이크 6.6초 녹음의 실제 GPU 처리/결과 복원 통과. `scripts/check_demo_results.py`의 합성 발화로 두 화자의 주문 변경 표시, 이름 저장, 변경 이력, JSON 다운로드, 320/390/1440px 화면도 통과했다. 합성 결과 테스트는 음성 모델 정확도 검증과 구분한다. 사용자용 서버 이력은 비어 있는 상태로 준비했다.

## 공모전 SDK 연결 범위

2026-11-12 매장 추가 검증: 자동 검사 21개 통과. 실제 Qwen 추론으로 세 매장 각각 두 화자의 주문과 메뉴 변경을 검증했다(`scripts/check_store_orders.py`). 메뉴 변경 시 다른 화자의 주문이 유지됨을 확인했다. 이 검증은 합성 텍스트 입력이며 실제 사람 녹음의 인식 정확도와 구분한다.

현재 위치는 브라우저 Geolocation, 지도는 Leaflet/OSM, 길 안내는 외부 Google Maps 링크를 사용한다. FusedLocation SDK와 NaviHelper SDK는 현재 웹 데모에서 실행하지 않는다. 목적지/좌표/매장 ID는 `trip.json`과 `navigation_request.json`에 저장하여 Android SDK 어댑터에 연결할 수 있게 했다. 현재 버전을 SDK 연동 완료본으로 제출해서는 안 된다.
